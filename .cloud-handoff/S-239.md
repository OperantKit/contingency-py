## 調査で見つかった食い違い（文書 §4・§5 に詳細）

- hil.rs の `DRO` はキー `mode`、spec は `dro_type`。
- `Percentile.direction` の既定が spec/エンジン `above`、DSL/bridge `below`。
- `Percentile.target` は Rust が `"irt"` のみ、DSL は `IRT`（大文字）。Python は両方受ける。
- `AdjustingSchedule.target`: DSL は `delay|ratio|amount`、エンジンが実行できるのは `ratio|interval`。共通は `ratio` のみ。
- `Concurrent` の `cod_directional` と `punish` は両エンジンにあるが spec に無い（fixture も無い）。
- `Interpolate` は bridge が `count` を捨てて `onset` から幾何を当て推量している。
- `MatchingToSample`/`GoNoGo` の `iti` 既定が spec（1.0 / 5.0）と bridge（0.0）で違う。
- DSL の trial-based schema に `delay` が無い（文法にはあり、bridge は読む）。
- 整数パラメータは Rust が `as_u64` なので JSON の `5.0` を受けない。
